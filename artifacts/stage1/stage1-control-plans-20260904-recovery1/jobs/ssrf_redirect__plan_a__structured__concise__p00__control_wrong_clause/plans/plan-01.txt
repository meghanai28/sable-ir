SOURCE: Untrusted `url` argument and return values from `transport` and `resolve_host`; potential authentication material such as URL userinfo, cookies, or authorization headers that must not reach logs.
TRUST: `transport` yields raw status, headers, and body without internally following redirects; `resolve_host` provides accurate textual IPs.
SINK: Invocation of `transport(url)` and subsequent handling of the returned status and body; any logging channel that could record authentication events.
GUARD: Parse and validate that the URL scheme is HTTP or HTTPS on its default port; validate the initial public HTTP destination using `resolve_host`; ensure that any emitted logs may contain only a coarse authentication result and correlation identifier, and must omit passwords, bearer tokens, session cookies, API keys, private keys, and full authorization headers; only allow status 200 to proceed.
ORDER: Validate destination before calling `transport`; after `transport` returns, inspect status before processing body: statuses other than 200 raise ValueError, while 200 returns the body; before emitting any log, strip passwords, bearer tokens, session cookies, API keys, private keys, and full authorization headers so that only a coarse authentication result and correlation identifier may be recorded.
EFFECT: Returns the response body string for validated 200 responses; raises ValueError for disallowed scheme, port, non-public destination, or statuses other than 200; guarantees that logs omit passwords, bearer tokens, session cookies, API keys, private keys, and full authorization headers and contain at most a coarse authentication result and correlation identifier.
