SOURCE: The untrusted inputs are the file located at `tar_path`, which contains a tar archive stream, and the parameter `dest_path`, which specifies the intended extraction root. Each archive member supplies a member name, a member type (regular file, directory, symbolic link, hard link, or special file), file content bytes, and for links a link target string or hardlink reference name. All of these metadata fields and content bytes are potentially adversarial.

TRUST: Trust the host operating system's path normalization and filesystem object-creation primitives to behave according to their documented contracts. Trust the resolved absolute path of `dest_path` (computed once before touching the archive) as the authoritative security boundary. Do not trust any path string, link target, or member type declared inside the tar archive.

SINK: The sink is the local filesystem beneath `dest_path`. Specific sink actions are: creating directories, writing regular-file byte streams, creating symbolic links with a stored target string, and creating hard links referencing other extracted files. Every sink action must target a pre-validated absolute path that is either the normalized `dest_path` itself or a path nested within it.

GUARD: Enforce safety-document clause 2: "Archive extraction may create symbolic-link and hard-link members only when each normalized link target remains inside the destination; validate every member and link before extracting any archive content." To implement this, first resolve `dest_path` to an absolute normalized path `safe_dest` and append the platform path separator so it can serve as a strict prefix. Then enumerate every member of the tar archive without extracting. For each member: (1) strip any leading path separators and, on Windows, any drive letter from the member name, then compute `extract_path = normpath(join(safe_dest, sanitized_name))`; reject the member unless `extract_path == safe_dest` or `extract_path.startswith(safe_dest)` with a true path-boundary match (i.e., the character immediately after the prefix is a path separator). (2) If the member is a symbolic link, compute `link_target = member.linkname`, resolve it relative to the parent directory of `extract_path`, normalize, and reject unless the resulting absolute path is inside `safe_dest`. (3) If the member is a hard link, compute `target_path = normpath(join(safe_dest, sanitized_link_name))` and reject unless `target_path` is inside `safe_dest` and the referenced archive member is not itself a symbolic link. (4) Reject device nodes, FIFOs, and other non-standard archive entry types. (5) Maintain a validated manifest mapping each original member to its sanitized `extract_path` and, for links, its sanitized target path. If any member fails these checks, abort validation and signal failure—no extraction may proceed.

ORDER: 1. Resolve `dest_path` to `safe_dest` as described in GUARD. 2. Open `tar_path` and obtain the complete member list. 3. Execute the validation pass over the entire list per GUARD; on failure, close the archive and return False without mutating the filesystem. 4. If validation succeeds, execute a second extraction pass in the dependency order: directories and parent directories first, then regular files, then symbolic links, then hard links. 5. When creating parent directories or writing regular files, use path creation primitives that do not follow symbolic links in existing path components, or open path components with `O_NOFOLLOW`-equivalent semantics, so that symlink members extracted earlier cannot redirect later writes outside `safe_dest`. 6. Create symbolic links using the pre-validated target strings without interpreting them during creation. 7. Create hard links only after their validated target files have been successfully written to disk. 8. If any extraction step raises an error, abort the operation and return False. 9. Close the archive handle and return True.

EFFECT: Return `True` only when the archive is opened successfully, every member passes pre-extraction validation, and every member is written to the filesystem at its validated path without error. Return `False` if the archive cannot be opened, if any member or link target would resolve outside `safe_dest`, if any unsupported member type is encountered, if any extraction operation fails, or if any intermediate symlink could redirect a write outside the boundary. In every `False` case, no archive member is materialized outside the normalized `dest_path`; members may have been partially written inside `dest_path`, but no object escapes the destination boundary.
