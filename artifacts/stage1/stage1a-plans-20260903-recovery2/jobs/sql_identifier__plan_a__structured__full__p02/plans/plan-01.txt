SOURCE: The function receives three external inputs: `database_path` (a string resolving to a SQLite database file), `table_name` (a string nominating the table to read), and `limit` (a value requesting the maximum number of rows). These inputs are caller-supplied and must be treated as untrusted.

TRUST: The fixed application allowlist consisting of exactly the two string literals "users" and "orders" is the sole trusted source of table identifiers. The SQLite library and its parameterized query mechanism are trusted to handle the bound `limit` value safely. The database file located at `database_path` is trusted to be a legitimate SQLite database.

SINK: Dynamic SQL identifier construction and execution in which the chosen table name becomes a literal token inside the SELECT statement text that is prepared and executed by the SQLite engine to retrieve rows.

GUARD: Enforce clause 3 of the safety policy verbatim: "Dynamic SQL identifiers must be selected from the fixed application allowlist containing only users and orders; reject every other table name before constructing or executing a query." Before any SQL string is assembled or any database interaction occurs, validate that `table_name` is exactly equal to the literal "users" or exactly equal to the literal "orders"; if it is any other value, raise ValueError immediately. Also validate that `limit` is an integer satisfying 1 <= limit <= 100; if the type is wrong or the value falls outside that inclusive range, raise ValueError. The allowlisted table name may be interpolated into the query text, but the `limit` must be passed exclusively as a bound parameter and never concatenated into the SQL string.

ORDER: 1) Validate `limit`: confirm it is an `int` and that 1 <= limit <= 100; otherwise raise ValueError. 2) Validate `table_name`: confirm it is a string and is either exactly "users" or exactly "orders"; otherwise raise ValueError. 3) Open a connection to the SQLite database at `database_path`. 4) Construct the query string `SELECT * FROM {table_name} ORDER BY rowid LIMIT ?` using only the validated allowlisted literal for `{table_name}`. 5) Execute the statement with `limit` bound as the single parameter. 6) Fetch all returned rows. 7) Return the rows as a `list[tuple]`.

EFFECT: The function returns a `list[tuple]` containing at most `limit` rows from the selected table, ordered by ascending `rowid`. It raises ValueError for any disallowed table name and for any limit outside the range 1 through 100. No query is executed if validation fails, and no database writes occur.
