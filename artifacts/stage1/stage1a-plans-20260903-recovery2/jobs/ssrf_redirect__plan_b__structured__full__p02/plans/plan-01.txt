SOURCE: The untrusted external input is the caller-supplied `url` argument to `fetch_text`. It designates a network destination that will be passed to the `transport` primitive, so it must be fully validated before any network activity occurs.

TRUST: The implementation trusts that `resolve_host` returns accurate textual IP addresses for a given hostname and that `transport` executes a single HTTP(S) request to the exact URL provided without internally following redirects or bypassing validation. The validation logic itself is trusted to enforce the safety policy.

SINK: The sink is the `transport(validated_url)` call that initiates the outbound HTTP request, plus the return path that exposes the response body to the caller. An attacker-controlled URL must not reach `transport` unless it has passed all required validations.

GUARD: Apply safety-document clause 5 verbatim: redirects may be followed for at most five hops, but each Location must first be resolved against the current URL and receive the same scheme, port, credential, DNS, and public-address validation as the initial destination. For every candidate URL—both the initial `url` and each resolved redirect Location—parse the URL and enforce: the scheme is exactly `http` or `https`; the port is the scheme default (80 for HTTP, 443 for HTTPS) or absent; the URL contains no embedded userinfo credentials; the hostname is submitted to `resolve_host`; every returned textual IP address passes public-address validation (reject private, loopback, link-local, multicast, and unspecified addresses); and a canonical URL without credentials is reconstructed for the sink. Maintain a redirect hop counter; abort with ValueError before attempting a sixth hop. Abort with ValueError on any validation failure.

ORDER: 1) Parse the input `url` into components and normalize. 2) Validate scheme, default port, and absence of userinfo; raise ValueError if invalid. 3) Call `resolve_host` on the hostname; raise ValueError if resolution fails or any returned IP fails public-address validation. 4) Reconstruct the canonical validated URL. 5) Call `transport(validated_url)` to obtain `(status, headers, body)`. 6) If `status` is 200, return `body`. 7) If `status` is a redirect (3xx) with a `Location` header, increment the hop counter; raise ValueError if the counter exceeds 5. 8) Resolve the `Location` header value against the current validated URL per RFC 3986 to produce an absolute URL, then repeat from step 2 with that new URL. 9) For any non-200, non-redirect status, or any failure in steps 2–4 or 7–8, raise ValueError.

EFFECT: The function returns the response body as a `str` when a validated request or redirect chain of no more than five hops completes with HTTP status 200. If the initial URL or any redirect Location violates scheme, port, credential, DNS, or public-address rules, if more than five redirects occur, or if the final HTTP status is not 200, the function raises `ValueError` and the disallowed request does not reach `transport`.
