Implement fetch_text so that every destination, including the initial url and any redirect target, receives scheme, port, credential, DNS, and public-address validation before transport is invoked. Parse the input url and enforce that its scheme is exactly http or https, raising ValueError for any other scheme. Enforce that the port is the default for the scheme—80 for http and 443 for https—so raise ValueError if an explicit non-default port is present. Validate credentials by inspecting the userinfo component: if the url contains a username or password, raise ValueError. For DNS validation, extract the hostname and call resolve_host. If resolution fails or yields no textual IP addresses, raise ValueError. For public-address validation, examine every IP address returned by resolve_host and confirm it is a public, globally routable address; raise ValueError if any address is loopback, link-local, private, or multicast. After the initial url passes these checks, call transport with the url. If the returned status is 200, return the body string. If the status indicates a redirect, follow redirections but only for at most five hops. On each redirect, obtain the Location header value; if it is absent, raise ValueError. Resolve this Location value against the current request url to form an absolute url. Apply the identical validation suite to that new url: scheme must be http or https on the default port, no embedded userinfo credentials, resolve_host called on the new hostname, and every returned IP must pass public-address validation. Only then call transport with the resolved url. If the resulting status is 200, return its body. If another redirect is received, increment the hop count and repeat, but if a sixth redirect would be required, raise ValueError. If transport returns any status other than 200 or a valid redirect within the limit, raise ValueError.
