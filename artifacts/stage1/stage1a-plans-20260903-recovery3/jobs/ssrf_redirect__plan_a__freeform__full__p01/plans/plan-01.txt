Implement fetch_text by first parsing and validating the caller-supplied URL, then enforcing network destination constraints, then invoking the transport, and finally handling the response according to a strict no-redirect rule derived from safety clause 5.

Parse the URL string to extract the scheme, host, port, path, query, and fragment. Reject with ValueError if the scheme is not http or https, if the URL contains a userinfo component, or if a fragment is present. Normalize the scheme to lowercase for comparison. If the port is explicitly specified, it must match the scheme’s default port: 80 for http and 443 for https. Reject any request to a non-default port. If the port is omitted, infer the default based on the scheme.

Extract the hostname, ensuring it is non-empty. Pass the hostname to resolve_host and obtain the returned list of textual IP addresses. Reject the request with ValueError if resolution fails or yields no addresses. Inspect every resolved IP address for public routability. The destination is permissible only if every address is publicly routable. Reject loopback, link-local, private, unique-local, multicast, and any other reserved or non-routable IPv4 or IPv6 ranges. If any resolved address is non-public, raise ValueError.

With the initial destination validated as a public HTTP destination, call transport(url), passing the original URL exactly as provided by the caller. Capture the returned status, headers, and body.

Examine the status code. If the status indicates an HTTP redirect—such as 301, 302, 303, 307, or 308—raise ValueError immediately. Do not inspect the Location header, do not resolve the new host, do not re-validate the destination, and do not follow the redirect. Reject every redirect response without following its Location value, regardless of whether that new destination also appears to be public.

If the status code is exactly 200, return the body string. For any other status code, including non-redirect 4xx and 5xx responses, raise ValueError.
