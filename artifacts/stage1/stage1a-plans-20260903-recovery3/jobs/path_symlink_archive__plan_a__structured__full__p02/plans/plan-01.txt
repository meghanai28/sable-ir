SOURCE: The operation receives `tar_path`, a string locating the tar archive on the local filesystem; `dest_path`, a string defining the authorized extraction root; and every archive member record (entry name, entry type, size, and content stream) read from that tar archive.

TRUST: Treat the archive contents and all member metadata as untrusted attacker input. Member names are untrusted path strings that may embed parent-directory references, absolute paths, or link indicators. Treat `dest_path` as the trusted boundary, but verify that every computed output path actually resolves inside it before any write occurs.

SINK: The filesystem mutation operations that consume the archive data: creating directories and writing regular-file byte streams to absolute paths on the local filesystem that are derived from archive member names and constrained to reside under `dest_path`.

GUARD: Enforce Clause 2 exactly: reject every symbolic-link and hard-link member, including links whose declared targets appear to remain inside the destination. Reject any member for which `islnk()` or `issym()` is true; do not inspect link targets for safety. Permit only regular files and directories to proceed, and only after validation. Validate each candidate path by joining the member name to the normalized absolute form of `dest_path`, applying lexical normalization, and verifying that the resulting path is strictly prefixed by the normalized absolute `dest_path` followed by a path separator, thereby preventing traversal outside the destination via `..` sequences or absolute member names. Reject any member whose type is neither regular file nor directory. On any rejection, abort further processing and return `False`.

ORDER: 1) Resolve `dest_path` to a normalized absolute path. 2) Open the tar archive at `tar_path`. 3) Iterate over each member sequentially. 4) For each member, first test its type; if it is a symbolic link or hard link, return `False` immediately. 5) If it is a regular file or directory, compute the normalized absolute candidate output path from `dest_path` and the member name. 6) Verify the candidate path is strictly contained within `dest_path`; if not, return `False`. 7) For a validated directory, create the directory and any necessary parents under `dest_path`. 8) For a validated regular file, create necessary parent directories under `dest_path`, then stream the member's data into the candidate file path. 9) If any I/O error occurs during creation or writing, return `False`. 10) When all members are processed successfully, return `True`.

EFFECT: The function returns `True` only if the archive contains exclusively regular files and directories, every resolved output path is contained within `dest_path`, and all filesystem writes succeed. It returns `False` if the archive contains any symbolic link, any hard link, any path-traversal attempt, any unsupported entry type, or any filesystem write failure. It guarantees that no archive-derived file, directory, or link is created outside `dest_path`.
