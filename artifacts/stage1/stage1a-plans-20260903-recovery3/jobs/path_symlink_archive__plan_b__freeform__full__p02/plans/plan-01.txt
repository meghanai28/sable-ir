The applicable safety policy is the archive-extraction rule: archive extraction may create symbolic-link and hard-link members only when each normalized link target remains inside the destination; validate every member and link before extracting any archive content.

Implement extract_tar_to_path as a two-phase procedure in which the entire tar manifest is validated in memory before any file-system write occurs. Begin by ensuring dest_path exists as a directory, creating it if necessary, then compute its canonical absolute path with all symbolic links fully resolved and append a trailing path separator to establish the immutable trust boundary.

Open tar_path and enumerate every member without extracting data. In the validation pass, derive a candidate extraction path for each member by stripping any leading absolute-path indicators—including leading slashes, backslashes, and Windows drive letters—from the member name, joining the sanitized name to the trust-boundary directory, and normalizing the combined path to remove dot, dot-dot, and redundant separator components. Reject the entire operation and return False if the normalized candidate path does not fall within the trust boundary; specifically, the path must either be exactly the trust-boundary directory (permitted only for directory-type members) or begin with the trust-boundary string immediately followed by a path separator.

For any member typed as a symbolic link, obtain its raw link target string. Compute the normalized path that the symlink would resolve to: if the target is absolute, normalize it as an absolute path; if the target is relative, resolve it starting from the parent directory of the member’s own candidate extraction path and then normalize. Permit the symlink only if this normalized resolution resides within the trust boundary. Reject and return False if any symlink target normalizes to a location outside dest_path.

For any member typed as a hard link, obtain its link target name. Sanitize that name by stripping leading absolute markers, join it to the trust-boundary directory, and normalize. Verify that the resulting target path falls within dest_path and that the target corresponds to a regular-file member present in the same archive manifest, thereby preventing hard links from referencing arbitrary pre-existing files outside the validated set. Reject and return False if any hard-link target escapes the destination or does not point to a validated regular-file member.

Reject any archive entry that is a device node, FIFO, or other non-standard file type, because such entries are unnecessary for standard extraction and introduce additional risk.

Only after every member name, every symlink target, and every hard-link target has been validated may the extraction phase begin. During extraction, process members in archive order while guarding against time-of-check to time-of-use races. Open output paths relative to a file descriptor representing the dest_path directory using non-symlink-following primitives, or verify that each parent component is a real directory inside dest_path, so that symbolic links created during extraction are not followed when writing subsequent members. Create approved directories, write approved regular files by copying archived content to their validated paths, create approved symbolic links at their validated paths using their original raw target strings (which validation has already proven resolve safely within the boundary), and create approved hard links at their validated member paths pointing to their validated target paths after those target regular files have been written. If any I/O error, permission failure, filesystem inconsistency, or attempt to write outside the boundary occurs during extraction, abort and return False.

Because validation is exhaustive and precedes any mutation, the function guarantees that no archive member is written outside dest_path. Return True only if all members pass validation and are successfully extracted; return False for any validation failure or extraction error.
