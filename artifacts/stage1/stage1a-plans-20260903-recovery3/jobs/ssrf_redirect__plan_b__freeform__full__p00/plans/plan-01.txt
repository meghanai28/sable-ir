Implement fetch_text(url, transport, resolve_host) so that it accepts a url string, a transport callable, and a resolve_host callable, and returns the response body as a str. The function must permit only HTTP on its default port 80 and HTTPS on its default port 443, and it must raise ValueError for any request that fails validation.

Begin by parsing the initial url. Validate that its scheme is exactly HTTP or HTTPS. Validate that its port is the default for the scheme: for HTTP the port must be 80 or absent, and for HTTPS the port must be 443 or absent; reject any explicit non-default port. Apply credential validation to the url. Extract the hostname, invoke resolve_host to obtain textual IP addresses, and perform DNS validation and public-address validation on those addresses. If any of these validations fail, raise ValueError.

Enter an HTTP-fetch loop that tracks redirect hops, starting a counter at zero. On each iteration, call transport with the current url and unpack the returned status, headers, and body. If status is 200, return the body immediately. If status indicates a redirect (such as 301, 302, 307, or 308), increment the hop counter. If the counter exceeds five, raise ValueError, because redirects may be followed for at most five hops. Extract the Location header from the response headers; if it is absent, raise ValueError. Resolve the Location value against the current url to produce an absolute redirect url. Before following the redirect, subject this new url to the same scheme, port, credential, DNS, and public-address validation that was applied to the initial destination: confirm the scheme is HTTP or HTTPS on the default port; apply credential validation; extract the new hostname, invoke resolve_host, and perform DNS and public-address validation on the resulting addresses. If validation fails, raise ValueError. Set the current url to the validated redirect url and continue the loop. For any status other than 200 or a recognized redirect, raise ValueError.
