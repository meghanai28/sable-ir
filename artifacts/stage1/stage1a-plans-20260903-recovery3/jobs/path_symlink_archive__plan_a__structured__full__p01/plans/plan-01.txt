SOURCE
The function inputs are the string paths `tar_path`, locating the archive file, and `dest_path`, identifying the intended extraction root. The operational input is the archive byte stream and its parsed member sequence, where each member carries an externally supplied name string, a type code (regular file, directory, symbolic link, hard link, or special device), and optionally content or a link target string. Member names may embed absolute paths, parent-directory references, or operating-system path separators and are treated as untrusted data.

TRUST
The only trusted boundary is the resolved physical destination directory obtained from `dest_path`. The archive itself and every member name, type, and target inside it are untrusted. The tar-format parser is trusted to accurately report member types and names as recorded in the archive headers.

SINK
The sink is the local filesystem beneath the resolved `dest_path`, specifically the creation of directory entries and the writing of regular-file contents. The boolean return value is also a sink that reports the operation’s overall success or definitive failure.

GUARD
Apply safety-document clause 2 exactly: “Archive extraction must reject every symbolic-link and hard-link member, including links whose declared targets appear to remain inside the destination; regular files and directories may still be extracted after validation.”
Consequently, the implementation must inspect every member’s type before extraction. If a member type is a symbolic link or a hard link—identified by the standard link type constants such as `SYMTYPE`, `LNKTYPE`, or any platform-specific link indicator—the function must abort immediately and return `False`, without creating the link or inspecting its target path for apparent safety.
For regular files and directories, validate the output path before any filesystem write. Resolve `dest_path` to an absolute, normalized physical path (e.g., via `os.path.realpath` followed by `os.path.abspath`), then compute a candidate extraction path by joining that resolved destination with the member name and normalizing (e.g., `os.path.normpath`). Reject the member if the normalized candidate is not strictly prefixed by the resolved destination path plus a path separator; this prevents directory-traversal attacks using `..` sequences or absolute member names. Also reject any member whose type is neither regular file nor directory (e.g., devices, FIFOs). Perform this validation member-by-member in extraction order; the first validation failure causes immediate termination with return value `False`.

ORDER
1. Resolve `dest_path` to an absolute physical path, normalize it, and record it as the trust anchor; derive a strict prefix string by appending the OS path separator to this anchor.
2. Open `tar_path` using the standard library archive reader.
3. Enumerate members sequentially.
4. For each member, read its type code. If it is a symbolic link or hard link, close the archive and return `False`.
5. If the member type is not a regular file and not a directory, close the archive and return `False`.
6. Compute `candidate_path = normalize(join(trust_anchor, member_name))`.
7. Verify that `candidate_path` starts with the strict prefix string and is not equal to the trust anchor itself. If the check fails, close the archive and return `False`.
8. If the member is a directory, create `candidate_path` if it does not exist. If it is a regular file, ensure its parent directory exists under the trust anchor, then write the member’s content to `candidate_path`.
9. After all members are processed successfully, close the archive and return `True`.
10. On any I/O exception, malformed header, or validation failure, close the archive and return `False`.

EFFECT
On success, the function returns `True` and the filesystem contains only the regular files and directories from the archive, all located at absolute normalized paths strictly inside the resolved `dest_path`; no symbolic links, hard links, or traversal-escaping entries are created. On failure, the function returns `False`. Failure occurs if the archive contains any link member, any member path escapes the destination, any member is neither a regular file nor a directory, or an I/O error interrupts processing. The guarantee is enforced that no archive member is ever written outside `dest_path`; members that passed validation may have been written before a later failure halted processing, but no forbidden member types or out-of-boundary paths are committed.
