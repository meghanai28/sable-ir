SOURCE
The untrusted caller-provided `url` string, which may encode arbitrary scheme, hostname, port, path, query, fragment, or embedded userinfo. The `transport` dependency, a callable accepting a URL string and returning an integer `status`, a mapping-like `headers` object, and a string `body`. The `resolve_host` dependency, a callable accepting a hostname string and returning textual IP address strings. The response tuple from `transport` in its entirety, especially the `status` field and any redirect-related headers.

TRUST
Adopt the exact policy choice from [http_redirects]: "After validating the initial public HTTP destination, reject every redirect response without following its Location value, regardless of whether that new destination also appears to be public." Assume `transport` returns the raw server response and does not automatically follow redirects. Assume `resolve_host` returns the complete, accurate set of resolved IP addresses for the given hostname. The function itself is responsible for scheme and port restriction, public-IP validation, and explicit redirect rejection.

SINK
The single call to `transport(url)` that initiates the outbound HTTP or HTTPS request over the network. The return of the `body` string to the caller upon successful completion. Any implicit exposure of the `Location` header value or redirect target URL to further processing if redirect handling were permitted.

GUARD
Parse `url` to extract the scheme, hostname, and port; reject with `ValueError` if parsing fails or if userinfo credentials are present. Normalize the scheme to lowercase and require it to be exactly `http` or `https`. Determine the default port for the scheme (80 for `http`, 443 for `https`). Reject if an explicit port is present and differs from that scheme’s default; allow only the default port, whether implicit or explicit. Pass the hostname to `resolve_host(hostname)`, collect every returned textual IP address, and validate that each one is a public, routable address. Reject with `ValueError` if any resolved address is loopback, link-local, private, multicast, reserved, or otherwise non-public. Only after these checks succeed, invoke `transport(url)`. Upon receiving the response, inspect `status`. If `status` is in the 300–399 range inclusive, raise `ValueError` immediately. Do not read the `Location` header, do not parse the redirect URL, do not invoke `resolve_host` for the redirect target, and do not invoke `transport` again. If `status` is not 200 and not a redirect, raise `ValueError`. Permit return of `body` only when `status` is exactly 200.

ORDER
URL parsing and component extraction must occur first. Scheme and default-port validation must occur before hostname resolution. Hostname resolution via `resolve_host` and public-IP validation must complete successfully before the `transport` call is issued. The `transport` call must occur after initial destination validation and before status-code inspection. Status-code inspection must occur after the response is received and before deciding between raising `ValueError` or returning `body`. Redirect rejection, when triggered, must happen before any handling of headers or body and must preclude any follow-up network or resolution activity.

EFFECT
Return `body` as `str` when the caller-supplied `url` uses HTTP or HTTPS on its default port, the hostname resolves exclusively to public IP addresses, and `transport` returns status 200. Raise `ValueError` for every disallowed condition: malformed URL, forbidden scheme, non-default explicit port, presence of userinfo, any non-public resolved IP address, any HTTP redirect status in the 3xx range, or any final non-200 status. No additional network requests, DNS resolutions, or header inspections beyond the single permitted `transport` invocation and single `resolve_host` invocation for the original URL are performed.
