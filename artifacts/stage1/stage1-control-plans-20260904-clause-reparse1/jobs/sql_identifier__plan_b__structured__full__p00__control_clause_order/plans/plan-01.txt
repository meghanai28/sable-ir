SOURCE
The function fetch_rows receives three caller-supplied inputs: database_path, a string locating the SQLite database file; table_name, a string nominating the target table; and limit, an integer specifying the maximum number of rows to return.

TRUST
database_path is trusted only as a filesystem locator to an on-disk SQLite database. table_name is untrusted attacker-controlled text and must never be interpolated into SQL before validation. limit is untrusted numeric input that must be range-checked. The sqlite_master catalog is the trusted authority for existing table names. The schema lookup result is trusted only after confirming that the named table exists and is not a system table.

SINK
The SQL SELECT statement execution, specifically the point where the validated, quoted table identifier and the bound LIMIT are submitted to the SQLite engine to retrieve rows.

GUARD
- Validate that limit is an integer satisfying 1 <= limit <= 100; raise ValueError otherwise.
- Execute a parameterized schema lookup query against sqlite_master (or sqlite_schema) using table_name as the sole bound parameter, e.g., SELECT name FROM sqlite_master WHERE type = 'table' AND name = ?.
- If the lookup returns no row, raise ValueError for a disallowed table.
- Inspect the returned name: if it begins with "sqlite_" identifying a system table, raise ValueError for a disallowed table.
- After successful validation, transform the table name into a safely quoted SQLite delimited identifier by enclosing it in double quotes and escaping any internal double-quote characters by doubling them.
- Bind the already-validated limit value as a query parameter in the final SELECT execution; do not concatenate limit into the SQL text.

ORDER
1. Validate limit is within the closed range [1, 100]; raise ValueError if invalid.
2. Open a connection to the database at database_path.
3. Execute the parameterized schema lookup query, binding table_name as the parameter.
4. Fetch the lookup result row; if none exists, raise ValueError.
5. Verify the returned name does not denote a system table by rejecting names with the prefix "sqlite_"; if it does, raise ValueError.
6. Quote the validated table name using SQLite double-quote delimited identifier syntax.
7. Construct the final SQL text: SELECT * FROM <quoted_identifier> ORDER BY rowid LIMIT ?, with a literal question mark placeholder for the limit.
8. Execute the query, binding limit as the parameter value.
9. Fetch all returned rows and provide them to the caller.

EFFECT
Return a list of tuples containing at most limit rows from the specified table, ordered by rowid. Raise ValueError when limit is outside 1 through 100 or when table_name is absent from the schema or designates a system table. The operation must be read-only and produce no persistent database changes.
END_PLAN
