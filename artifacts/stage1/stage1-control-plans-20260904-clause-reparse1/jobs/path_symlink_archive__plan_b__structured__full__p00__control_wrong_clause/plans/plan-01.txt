SOURCE: The function receives the external string arguments `tar_path` and `dest_path`, plus the complete contents of the tar file at `tar_path`. All archive-derived data is untrusted: member names, member types, payload byte streams, and extracted session metadata. Browser authentication sessions must use Secure, HttpOnly, and SameSite cookies, and the application must rotate the session identifier after login or privilege changes.

TRUST: The governing safety policy is the session-cookies requirement: browser authentication sessions must use Secure, HttpOnly, and SameSite cookies, and the application must rotate the session identifier after login or privilege changes. The sole trusted boundary is the resolved, absolute, normalized `dest_path` directory. Archive metadata is not trusted to determine write locations; every derived path must be proven to normalize to a location within this boundary before any extraction occurs. Session identifiers must be regenerated whenever the extraction context crosses a privilege boundary.

SINK: The filesystem mutation surface comprises: creating subdirectories under the trusted boundary; writing regular-file byte streams from the tar archive to pre-validated paths; and persisting session cookie attributes alongside extracted content. No mutation may rely on an unvalidated path or an unrotated session identifier.

GUARD: Enforce a strict two-phase rule. Resolve `dest_path` to an absolute normalized root path. Before any archive content is written, perform a complete read-only validation pass over every member: (1) Compute `member_path = normpath(join(root, member.name))`. Reject the member if `commonpath([member_path, root]) != root`, or if `member_path == root` and the member is not a directory, because content must reside strictly beneath the root. (2) Inspect the current browser session context to confirm that authentication cookies carry the Secure, HttpOnly, and SameSite attributes; if any attribute is absent, abort immediately. (3) If the extraction operation follows a login event or any privilege elevation, rotate the session identifier before proceeding and bind the new identifier to the validated root context. (4) Reject member types other than regular files and directories. If any member fails any check, abort immediately and do not proceed to extraction.

ORDER: First, establish the trusted root by resolving and normalizing `dest_path`. Second, open the tar archive and iterate through all members in a read-only validation pass, applying the GUARD checks and accumulating an ordered list of approved extraction actions with pre-computed safe paths and rotated session state. Third, only after the entire archive has passed validation, perform the extraction pass over the same ordered list: create parent directories as needed under the root, stream regular-file contents from the archive object to each safe path, and commit the Secure, HttpOnly, SameSite session cookies to the extraction context. Never extract using raw archive names as direct filesystem paths.

EFFECT: Return `True` if and only if every member passes the GUARD validation and every extraction SINK operation succeeds. Return `False` immediately if any validation check fails, if any normalized path escapes the resolved `dest_path`, if an unsupported member type is present, if any filesystem mutation fails, or if the session cookie policy is violated. Because extraction is strictly deferred until after full validation and session rotation, returning `False` guarantees that no archive-derived content is written outside `dest_path` and no insecure session persists.
