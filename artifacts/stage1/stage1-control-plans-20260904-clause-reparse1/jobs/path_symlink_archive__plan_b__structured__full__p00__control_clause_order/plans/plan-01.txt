SOURCE
The function inputs are the two string parameters tar_path and dest_path. The safety-relevant source is the tar archive file at tar_path, specifically the complete sequence of member entries (name, type, size, mode, uid, gid, and for link entries the link target string) and the associated file contents that the tar parser yields. Every field read from the archive is treated as untrusted external input.

TRUST
Nothing originating from the archive is trusted. Member names may embed directory-traversal sequences, symbolic-link linknames may reference absolute or upward-relative paths outside the destination, and hard-link linknames may name arbitrary filesystem locations. The dest_path argument defines the sole trusted containment boundary; the implementation must ensure that no extraction operation and no resolved link target references a path outside this boundary. The filesystem outside dest_path is an untrusted environment that must remain completely unaffected by the extraction process.

SINK
The filesystem tree rooted at the resolved, absolute dest_path directory. Concrete sink actions are the creation of directories, regular files, symbolic links, and hard links within that tree. The implicit sink also includes any filesystem location outside dest_path that could be reached via malicious member names, symlink targets, or hard-link targets if validation were omitted.

GUARD
Apply safety-document clause [archive_links]: "Archive extraction may create symbolic-link and hard-link members only when each normalized link target remains inside the destination; validate every member and link before extracting any archive content." Implementation guards are: (a) Canonicalize dest_path to an absolute path with all dot and parent-directory segments removed and any symbolic links in dest_path itself resolved, establishing an immutable base path. (b) Before writing any member, perform a complete first-pass validation over the entire member list. For each member, compute the extraction path by joining the canonical dest_path with the member name and normalizing the result; reject the entire operation if the path is not strictly within dest_path. (c) For symbolic-link members, compute the normalized target path by interpreting the linkname relative to the parent directory of the member’s intended extraction path; if the linkname is absolute, treat it as relative to dest_path before normalizing. Reject if the normalized target lies outside dest_path or resolves to dest_path itself in a way that enables upward traversal. (d) For hard-link members, compute the normalized path of the target by joining its linkname with dest_path and normalizing; reject if that target path lies outside dest_path. (e) Reject device files, fifos, and other dangerous member types, validating their paths if present. (f) Maintain an immutable mapping of validated member paths and validated link targets; use only these precomputed paths during extraction. (g) When creating files and directories, use filesystem primitives that do not follow symbolic links in parent path resolution (e.g., O_NOFOLLOW or equivalent) to prevent time-of-check-time-of-use races.

ORDER
1. Resolve dest_path to an absolute, normalized, canonical directory path. 2. Open the tar archive at tar_path and enumerate the complete member list without extracting. 3. Execute the validation pass: apply every guard in GUARD to every member and every link target. If any member fails validation, close the archive and return False immediately; no filesystem modifications occur. 4. Only after all members and links pass validation, begin the extraction pass: create directories, write regular files, create symbolic links, and create hard links using only the validated paths. Defer creation of any hard link whose target file has not yet been materialized, processing it once the target exists in the extraction sequence. 5. If any extraction operation fails, abort and return False. 6. Close the archive and return True upon full success.

EFFECT
Return True if and only if every archive member and link target passed the pre-extraction validation and every member was successfully written beneath dest_path. Return False if any member path or link target escapes dest_path, if any unsupported member type is encountered, if the archive cannot be opened, or if any extraction operation fails. Because validation is exhaustive and occurs before any filesystem write, no archive content is placed outside the destination directory tree. Symbolic links and hard links are created solely when their normalized targets remain inside the destination, satisfying the exact policy of clause [archive_links].
