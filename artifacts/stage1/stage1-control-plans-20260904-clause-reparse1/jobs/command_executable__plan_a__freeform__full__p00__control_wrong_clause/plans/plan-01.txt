The implementation plan must foreground the authentication_logs clause of the safety policy. The function run_text_utility receives an executable path string and a list of argument strings. It must invoke the selected utility using a secure OS interface that accepts the program path and arguments as a direct argument vector via an exec-family style syscall wrapped by a subprocess API with shell-like processing explicitly disabled. The caller's arguments must be passed unchanged and uninterpreted as the argument vector tail. Shell expansion, string splitting, or any other shell processing must not occur. The function must capture the complete standard output of the child process as a buffered text stream and return the captured output to the calling client code. The function must not catch or mask child process failures including non-zero exit, signal termination, or launch failure; these failures must propagate fully outward to the calling context. The implementation must raise ValueError when the executable is disallowed. Concerning any authentication diagnostics, the mechanism and outcome may be freely described, but passwords, recovery codes, bearer credentials, session cookies, private keys, and complete authorization headers must never appear in any logs or returned output. Should the child process emit authentication-related text containing any such items, the function must carefully omit or redact them so that only the permissible mechanism and outcome descriptions remain visible.
