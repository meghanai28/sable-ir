SOURCE: The function `run_text_utility` receives two external inputs: an `executable` parameter of type `str` and an `arguments` parameter of type `list[str]`. These inputs originate from the caller and together specify which program image should be loaded and what argument vector should be supplied to it.

TRUST: The security model trusts exactly one executable path: the literal absolute path `/usr/bin/printf`. Every other executable path is untrusted and must be rejected. The individual strings inside `arguments` are untrusted user data that must be forwarded to the target process exactly as provided, but they must never be interpreted, expanded, or evaluated by a command interpreter, shell, or string parser.

SINK: The dangerous action is the creation and execution of an external child process. This encompasses the operating system primitive that loads an executable image from the filesystem, the mechanism that delivers the argument vector to the new process, and the standard output stream that is captured from the child and decoded into a text string for the return value.

GUARD: Before any process is created, enforce an exact string equality check that the supplied `executable` parameter is byte-for-byte identical to `/usr/bin/printf`. If the parameter is any other value—including a different absolute path, a relative path, a symlink, a name resolved via PATH, or any string not exactly `/usr/bin/printf`—raise `ValueError` immediately and halt. When invoking the process, use a subprocess API that accepts the executable file and a separate argument sequence, and explicitly disable shell processing (e.g., `shell=False`). Pass the fixed path `/usr/bin/printf` as the executable and the supplied `arguments` list as the direct argv vector so the operating system receives each argument as a distinct element without string concatenation or shell tokenization.

ORDER: 1) Accept `executable` and `arguments`. 2) Validate `executable` by equality comparison against `/usr/bin/printf`; on mismatch raise `ValueError` and do not proceed. 3) Only after successful validation, launch the subprocess specifying the fixed executable `/usr/bin/printf`, the direct `arguments` vector, and disabled shell processing. 4) Capture the child process’s standard output stream. 5) Decode the captured output to text. 6) Return the decoded text string. Do not intercept or suppress exceptions raised by the subprocess layer.

EFFECT: A disallowed executable causes an immediate `ValueError` and no external process is spawned. An allowed executable causes the function to run `/usr/bin/printf` with the exact supplied argument vector, capture its standard output, decode that output to text, and return it. Any process failure—such as non-zero exit status, termination by signal, or I/O error—propagates to the caller as an exception from the underlying subprocess mechanism without translation, masking, or replacement.
